# Component Guidelines

> How components are built in this project.

---

## Component Structure

- Function components only. Hooks at the top, before any early return.
- `TaskDetail` is the reference for conditional data: it calls all hooks, then `if (!task) return null`.
- One component per file; helpers used by only one component stay at the bottom of that file (`WelcomeCard`, `SortableTaskRow`).
- Components read store state through individual selectors:

```tsx
const db = useStore((s) => s.db);
const setMyDay = useStore((s) => s.setMyDay);
```

- Do not subscribe to the whole store object and destructure; it re-renders on every keystroke.
- Sidebar layout follows Microsoft To Do without text section headings: 我的一天 → 固定「任务」默认清单 → 重要 / 计划内 / 全部 / 已完成 → divider → custom lists/groups → inline new-list input. The first two rows are the basic section; the four smart rows the smart-list section; custom lists/groups the third. The footer pairs `新建列表` with an icon-only `创建新组` button; 同步/设置 live in the account dropdown opened from the brand. The inline new-list input commits on both Enter and blur (a non-empty name creates the list and opens it; an empty name just cancels), and Escape cancels — never require Enter alone, since users click away to finish.
- The fixed default list uses `DEFAULT_LIST_ID`: it is always present, is not draggable/groupable, cannot be renamed or deleted, and always uses the house icon in the sidebar and title. QuickAdd from smart views targets it; the list view itself targets that list. Its theme is background-only; a stored emoji/color is ignored.
- The account row uses a circular avatar + identity resolved by `profileDisplay(db.settings)` (`profileName` fallback `MacroHard Todo`; `profileSubtitle` fallback `webdavUser` fallback omitted) and no chevron; clicking the row opens the account menu, clicking the avatar opens the image picker, and `SettingsPage` edits avatar, `profileName`, and `profileSubtitle` via a narrow「编辑资料」modal. The search box below has the magnifier on the right and the placeholder `搜索`.
- The sidebar is resizable via `.sidebar-resizer` (clamped 200–420px, persisted in `settings.sidebarWidth`, double-click resets to 240). Selected nav rows use an inset `::before` highlight (2px vertical, 3px radius) with the accent bar in `::after` (3×16px, `--nav-accent`). Every nav row (smart lists, the default list, custom lists) uses a press/release interaction: `0.985` scale on pointer down (80ms ease-out) and a 200ms spring-back transition with overshoot on release (`cubic-bezier(0.34, 1.56, 0.64, 1)`), so repeated clicks on the current view still give feedback.
- At ≤760px the sidebar becomes a drawer: `App.tsx` tracks the breakpoint and a `sidebarOpen` state, renders `.sidebar-scrim`, and passes `onOpenSidebar`/`narrow` to `MainPane`. `.mobile-sidebar-toggle` (MenuIcon) sits at the header's top-left above the title; the sidebar is fixed at `min(320px, 84vw)` with z-index 90 over the z-index-89 scrim, sliding in via `.app-shell.sidebar-open`. Escape/outside click/view change closes it; the resizer is hidden. My Day's suggestion defaults closed when narrow; at ≤1100px `.suggest-panel`/`.detail-panel` are fixed right overlays instead of shrinking the main. Keep `tauri.conf.json` minWidth at 520 so the breakpoint is reachable (the running window needs a restart to pick up the native minimum).
- Sidebar counts use `.sidebar .nav-count` badges (20px circle/pill, radius 10px, `--nav-badge` / `--nav-badge-text`); the suggestion panel's count stays plain text.
- Smart-list icons use 16px in the sidebar and 24px in the title, 1.5 stroke width; per-item colors: My Day `--accent`, 全部/已完成 `--smart-red`, 重要/计划内/任务 `--text-secondary`. These system icons are fixed: the sidebar and title never use a theme emoji for them; 已完成 uses a circled check and 任务 uses the house.
- The app theme effect also calls `api.setTitleBarTheme(dark)` so the native Windows caption color (`#F3F3F3` / `#252423`) stays in sync with the sidebar.
- Group headers are `GroupRow`: group icon left, name (14px, 400, `--text`), collapse chevron right (up when expanded, down when collapsed); there is no `...` button. Clicking anywhere on the row toggles the group (the rename input is excluded); the chevron stops propagation so it never double-toggles. Give the row a physical press/release: `0.985` scale while `:active` (80ms ease-out) and a 200ms spring-back transition with overshoot on release (`cubic-bezier(0.34, 1.56, 0.64, 1)`), so it presses down while held and bounces on release. Double-click is not a rename shortcut; renaming and deletion live in the right-click menu (a just-created group still opens its inline name input automatically). For an empty group, the hover/drop highlight and bump belong to `.group-section` as one rounded block covering the header plus the `.group-empty` hint (class `group-section-empty`), never the header alone; clicking the hint also toggles. Non-empty groups keep the row-only surface. Right-click opens a context menu: empty groups show 重命名组 / 新建列表 / 删除组 (Delete hint); non-empty groups show 重命名组 / 新建列表 / 取消分组列表. For an empty group the right-click target is the whole section (header or the empty hint), and right-clicking inside the open menu must not reposition it. 新建列表 creates a custom list inside the group; 取消分组列表 keeps the lists and ungroups them. The whole group section is the drop target; empty groups show `.group-empty` at the list level (`padding-left: 38px`, gap 17px). Group lists use `.group-lists .nav-item` padding-left 32px, gap 26px, and the active accent bar at `left: 29px`.
- Custom lists without an emoji show a 16px `ListLinesIcon` tinted with `list.color` (accent by default), not a dot. The inline 新建列表 input row uses the same accent `ListLinesIcon` at 16px, so the pending row already looks like a list. A custom list whose name starts with an emoji (including flags, keycaps and ZWJ/skin-tone sequences) uses that leading emoji as its icon in the sidebar row and content title, and displays the remaining text as the name; `splitLeadingEmoji` in `src/lib/emoji.ts` does the grapheme split at render time — the stored name keeps the emoji, and rename inputs (sidebar and title) always start from the raw stored name. A stored theme emoji is only a fallback when the name has no leading emoji.
- One `DndContext` wraps the whole list area. Each section (ungrouped + every group) has its own `SortableContext`; group headers and the ungrouped drop zone are `group:<id>` / `group:ungrouped` droppables. Group headers themselves are not draggable — group order is creation order.
- Section building and drag resolution are pure helpers (`listSections`, `moveList` in `views.ts`); keep components free of that logic.
- The content header follows the Microsoft To Do metric grid: `.main-header` padding `40px 32px 6px 44px`; `.main-title` 28px/36px at weight 600 (Fluent Title2 — 32px read noticeably larger than Microsoft To Do); a 32×36px `.header-title-icon` slot + 8px gap (icon x=44px, title text x=84px); `.task-scroll` left 64px / right 56px; `.quick-add` margins `16px 66px 16px 64px`. Keep the title icon slot rendered on every view. Smart views and the default 任务 always use the fixed system icon (`SMART_TITLE_ICONS` / house in `MainPane.tsx`); only custom lists use name emoji → theme emoji → list glyph. System icons use `currentColor` so they turn white on theme backgrounds.
- The content subtitle is My Day-only (its date). Other views deliberately have no `N 项任务` / `N 项已完成` line; counts live in the sidebar badges. Do not reintroduce the count subtitle when adding header actions.
- Smart-view task rows include the source list name in their meta, including the 已完成 view; list views omit it because the current list is already the context. Keep `MainPane.rowProps.listName` keyed on `view.type === "smart"`, not on individual smart ids.
- The content header has exactly one `ViewMenu` (`MoreIcon`) per view. My Day additionally keeps the suggestion (lightbulb) button; do not re-add header search or palette icons.
- `ViewMenu` is a wide two-panel popover: a 280px main panel (排序依据 row, 主题 grid, list actions) plus a sort flyout. The 排序依据 flyout is an **independent Floating UI layer** anchored to that row (`useFloating` with `offset(12)`/`flip`/`shift`; left-start with a right-start fallback), not a flex sibling — opening it must not move or reflow the primary panel. The 12px offset clears the primary panel's padding/border so the submenu does not overlap the panel edge. Use `useHover` with `safePolygon()` (plus `useClick`/`useFocus`) so the pointer can move diagonally into the flyout without a close/reopen loop; do not close it from the primary panel's `onMouseLeave`. Keep the scale/fade animation on the **inner** `.main-menu-panel` / `.sort-flyout-inner`; the outer `.main-menu` / floating `.sort-flyout` must stay transform-free so the Floating UI coordinates are correct on the first frame. It lists the five `SORT_OPTIONS` with icons and the active check. The theme grid is 5 columns (无 + 14 Microsoft-matched `THEME_COLORS` gradients + 8 presets + upload, 44px tall tiles, 9px gaps) and is the same for every view; there is no separate 列表颜色 row. Keep the gradients subtle (stops close to the base, 135°) like Microsoft's color themes. Theme tile/color clicks keep the menu open. Reuse `.menu` for both panels, with `.main-menu-panel` fixed at 280px. Do not add the Microsoft-only print/email/pin actions.
- The theme grid has a dashed `+` tile for uploading a local background image (Tauri dialog + `attachmentAdd`); a stored custom image renders as an extra active tile before the `+` and reveals a top-right delete button on hover/focus. Use the `.theme-tile-wrap` + sibling `.theme-tile-delete` pattern (never nest buttons); deleting clears only the preset/image/color, preserving a custom list's existing emoji.
- Every view can have a theme, and all theme editing lives in `ViewMenu` (no standalone theme dialog): themes are `ListTheme.preset` / `ListTheme.image` / `ListTheme.color` stored in `list.theme` or `db.shared` (`mydayTheme` for My Day, `theme:<smartId>` for the rest). `THEME_COLORS` entries carry an optional `light` flag; `MainPane` matches the active gradient and adds `.on-light`, where `.main.on-image.on-light` switches title/subtitle/header actions/empty/suggestion/scrollbar to dark controls. `themePhoto` / `.on-photo` is true only for preset/custom-image themes; color themes do not get the frosted box.
- Empty states follow the theme kind: system views show an illustration (My Day's WelcomeCard art; the other smart/default/custom views use `.empty-illustration` — a tilted white paper + accent header + view badge + sparkles, not a plain icon tile). `.empty-state` fills the task area (`min-height:100%`) and centers a `.empty-inner` block in a flex row, matching the My Day `.welcome-wrap` vertical placement. Put the `.on-photo` frosted background on `.empty-inner`, never on the full-height `.empty-state`, so the box stays compact around the content. Give that frosted box a fixed `width: 320px` (`max-width: 100%`, 16px horizontal padding), not `fit-content`, so every list's box is the same size regardless of hint length; use `rgba(0, 0, 0, 0.64)` + `blur(18px)` so images behind it do not show through too strongly. The smart-view hint copy mirrors Microsoft To Do: 全部 `所有未完成的任务都会显示在此处。`, 计划内 `此处显示带有截止日期或提醒的任务。`, 重要 `尝试为一些任务加星标，以便在此处查看它们。` Keep these exact strings in `emptyHint` when adjusting layouts. On color gradients the inner content sits directly on the background (white or dark text by `on-light`); keep `.empty-state` and `.welcome-card` consistent visually.
- Color/image themes keep the empty task area clean: do not add Microsoft's faint horizontal list-row separators in the space below the last task. In Microsoft To Do they only appear inside the list content width and read as a rendering residue; our backgrounds stay flat. Microsoft's date-group headers (`今天 1`, collapsed groups) are also out of scope — the task list stays flat.
- The ViewMenu `fixedIcon` drops stored/selected emoji for system entries, so the sun/star/calendar/infinity/check/house icons never change; an existing custom-list theme emoji remains display-only. There is no separate `TaskList.color`/`setListColor`/color dot; the former palette is the `THEME_COLORS` background set. List management lives in `ViewMenu` plus the custom-list right-click menu; the default list only has `ViewMenu` actions.
- Custom-list rows (`SortableListRow`) expose a right-click menu: 重命名列表 (inline rename in the sidebar), 将列表移动到… (only when at least one group exists) with a hover flyout listing the groups plus 移出分组 for a grouped list, and 删除列表 (danger, Delete hint). The flyout opens to the right of the menu with a transparent hover bridge; choosing a group appends the list there and expands the target if collapsed. The default 任务 row has no context menu.
- Global `contextmenu` in `App.tsx` prevents the default WebView2 browser menu (refresh/save/print/inspect) across the app while still allowing native copy/paste inside `input`/`textarea`/`[contenteditable="true"]` or when text is selected; custom context menus (`GroupRow`, `SortableListRow`, `TaskContextMenu`) remain unaffected.
- Right-click menus positioned with `position: fixed` + `clientX/clientY` must be rendered through `createPortal(..., document.body)`, never inside the row/section. `.group-section` and `.nav-item` carry press/spring `transform`s, `SortableTaskRow` carries DnD `transform`s, and at ≤760px the whole `.sidebar` has a drawer `transform`; a transformed ancestor becomes the containing block for `fixed` descendants, so the menu first appears offset (and scaled) and only snaps to the cursor once the transform finishes. Portaled menus get `z-index: 100` (`.menu.group-menu`, `.menu.list-menu`, `.menu.task-context-menu`) so they stay above the drawer (z 90).
- Task rows support right-clicking via `TaskContextMenu` (managed as a single active menu in `MainPane` so opening one closes any other, closing on scroll/view change/Escape): toggles My Day (`Ctrl+T`), importance, and completion (`Ctrl+D`), quick due-date presets + portaled `DateTimePicker`, move-to-list flyout (auto-flips left near viewport right edge), and delete (`Delete`, via `confirmDelete`). `App.tsx` binds `Ctrl+T`, `Ctrl+D`, and `Delete` for the currently selected task when focus is outside editable fields and no modal/Settings is open.
- View-level task grouping is pure logic in `views.ts` (`sectionsForView`, `completedTasksForView`, `plannedBucketKey`, `plannedRangeTitle`, `defaultCollapsedSections`); `MainPane` only renders it. `sectionsForView` returns `[]` for flat views (`list` / `myday` / `important`); `planned` buckets incomplete tasks by effective date (`dueDate ?? reminderAt` date) into 已逾期 / 今天 / 明天 / 接下来 5 天 (`today+2`…`today+6`, title `M月d日,周X到M月d日,周X`) / 以后 (matching the sidebar `计划内` count, excluding completed tasks), while `all` and `completed` bucket by list in sidebar order (orphan tasks are skipped). Grouped views never use DnD; the flat path keeps `DndContext` + `SortableTaskRow`.
- Every section header (list/date groups and the bottom completed area) uses `SectionHeader`: a real `<button>` with `aria-expanded`, a 16px chevron, the title, and an optional count. `all` and `planned` pass a count; `completed` deliberately does not. `all` / `completed` rows omit the source list name (the group title carries it); `planned` keeps it.
- The bottom 「已完成 N」 area only appears for `list` / `myday` / `important` and defaults to collapsed (`defaultCollapsedSections`) to match the previous behavior; `planned` / `all` / `completed` never render it (`completedTasksForView` returns `[]`). Collapse state is local-only in `settings.collapsedSections[viewKey]` via `toggleSection`, so it survives restarts but is not synced.
- Deleting a list must not delete its tasks: `deleteList` moves every non-deleted task (including completed ones) to `DEFAULT_LIST_ID`, appending after the default list's current max `order` while preserving relative order and all task fields, then soft-deletes only the list.
- Importance stars in task rows are always visible: outline (`StarOutlineIcon`) when not important, filled (`StarFilledIcon`) with the `.on` class when important. The selected color is `var(--theme-accent, var(--star))`; completed/partial task checkboxes use `var(--theme-accent, var(--accent))` and `--theme-accent-hover`. `MainPane` sets both variables from `themeAccent(theme)` — the deepest gradient stop for color themes, `#687681` for preset/uploaded image themes, and no override when the view has no theme.
- `TaskDetail` renders a top-right `×` close bar (`.detail-topbar`), card-style sections (`.detail-card` / `.detail-block`), and a clean centered footer (`创建于 / 已完成于` + right `🗑`), mirroring the active view's `--theme-accent` / `--theme-accent-hover` via `themeAccent(viewTheme)`. Steps use circular checkboxes (`.step-check`), indented bottom dividers (`.step-body`), a portaled `⋮` menu (`标记为已完成 / 标记为未完成`, `提升为任务`, `删除步骤`), and a `+ 添加步骤` / `+ 下一步` row (label switches once any step exists) whose leading `+` morphs into an empty circle while focused/typing. Active My Day renders accent `已添加到“我的一天”` + `×`; reminders highlight in `.accent` only when upcoming (`reminderAt > Date.now()`) and drop to muted secondary text when past; overdue due dates use `.danger`; incomplete overdue recurring tasks show `.detail-cleanup` with 「跳转到当前任务」 backed by `nextOccurrenceOnOrAfter`.
- `DateTimePicker` wraps `react-day-picker` (`zhCN` locale, `weekStartsOn={1}`, custom `CalendarDropdown` replacing native `<select>`, optional 24h time inputs via `withTime`). Custom repeat editing lives in `RepeatDialog` (`<Modal narrow>`); its unit listbox (`.detail-select-menu.portaled`) and end-date `DateTimePicker` (`.date-picker-portal`) portal to `document.body` using button `getBoundingClientRect()` coordinates so modal overflow never clips them.
- Setting a recurrence rule on a task without a `dueDate` defaults `dueDate` to `todayISO()`. Monthly and yearly rules record `anchorDay` (1–31) and `anchorMonth` (0–11, yearly) from the base due date so `nextOccurrence` clamps to short months without permanent day drift; `describeRecurrence` renders Monday–Friday weekly rules as `工作日`.
- Settings is a full-window dedicated page (`SettingsPage`, controlled by `useStore.settingsOpen`), not a modal: sticky `← 设置` top bar + centered single-column layout (`max-width: 560px`) + profile header (`useAvatar`) + Fluent pill switches (`.toggle-switch`, `role="switch"` with `开`/`关`) + vertical theme radio group. Opening `SyncDialog` or `MigrationWizard` overlays on top of `SettingsPage` without closing it; `Escape` (when no modal/confirm is open) or global quick-add exits Settings cleanly. Keep `.settings-line` in `styles.css` because `SyncDialog` and `MigrationWizard` still rely on it. Keep settings self-evident through controls and layout (e.g., dropdown options like `关闭` / `7 天后` instead of raw `0` inputs with explanatory text); avoid adding small-print instructional paragraphs under setting items.
- Destructive deletes (task, custom list, empty group) route through `useStore.confirmDelete` + `ConfirmDialog` (`<Modal narrow>`) when `settings.confirmBeforeDelete` is enabled; non-destructive 「取消分组列表」 skips confirmation, and store mutation methods (`deleteTask`/`deleteList`/`deleteGroup`) stay direct synchronous actions.
- Sidebar smart-list visibility (`important`, `planned`, `completed`, `all`) is computed via `isSmartViewVisible` in `views.ts` (combining `settings.smartListVisibility` and `settings.autoHideEmptySmartLists`, while keeping the currently active smart view visible until navigated away). The `completed` smart list intentionally omits its sidebar count badge (still using `counts.completed` for auto-hide). `showDueTodayInMyDay` is centralized in `isTaskInMyDay` (`views.ts`) and shared across My Day tasks, completed tasks, counts, and suggestion exclusions; `DateTimePicker` reads `settings.weekStartsOn` (`0 | 1`).

## Props Conventions

- Type props inline for local components; export an interface only when reused (`TaskRowProps`).
- Reuse domain types from `src/lib/model.ts` instead of re-typing shapes.
- Pass callbacks, not store actions, into presentational components (`TaskRow` receives `onToggle`, `onSelect`).
- Optional props use `?`; prefer explicit `undefined` over `null` in new code (legacy `myDay` uses `string | null`).

```tsx
export interface TaskRowProps {
  task: Task;
  selected: boolean;
  onSelect: () => void;
  onToggle: () => void;
}
```

## Styling Patterns

- All styling lives in `src/styles.css` with CSS variables (`--accent`, `--bg-main`, `--text-secondary`, …). Dark mode is `:root[data-theme="dark"]`.
- Use inline styles only for dynamic data: theme colors, computed widths, `backgroundImage` from a theme.
- Reuse existing classes (`.nav-item`, `.task-row`, `.detail-row`, `.quick-add`, `.suggest-row`, `.welcome-card`). Add a new class rather than one-off Tailwind strings.
- `.task-row` is a card in every view, independent of whether the view has a background theme: use the `--task-card-bg`, `--task-card-border`, `--task-card-hover`, `--task-card-selected`, and `--task-card-shadow` tokens (1px border, 4px radius, 2px gap). Do not add `.main.on-image .task-row` or task-text/checkbox/star overrides; `.main.on-image` is for the page backdrop, white header, empty-state, suggestion, quick-add, and welcome surfaces only.
- The task list is a scroll container with a stable, thin, always-visible scrollbar (`--scrollbar-thumb` tokens, white-alpha thumbs on image backgrounds) and 8px bottom padding. The QuickAdd sits outside the scroll with a 16px top margin, creating a persistent page-background gap between the scroll viewport and the add bar at every scroll position; a right margin of 66px (56px content inset + scrollbar gutter) aligns the bar with the task cards. When the list overflows, the last task must scroll fully above the add bar. Do not rely on scroll-content padding alone for this gap — it is only visible at the end of the scroll.
- QuickAdd has three states: a normal trigger button (＋ 添加任务 in `--text`, no hint), a hover `#e8eceb` light surface (`--quick-add-hover`), and an editing task-card row with an empty checkbox, focused input, and `Enter 添加` hint. Use `.quick-add.editing` + the `--task-card-*` tokens; do not restore the always-visible input or the old blue `:focus-within` inset. Escape/empty blur returns to the trigger; Enter keeps the editing row active.
- Other image/theme surfaces use `.main.on-image` modifiers for white header text and contrast-aware overlays.
- Transitions are 120–200 ms ease; respect `prefers-reduced-motion` (already handled globally).

## Icons

- Import icons only from `src/components/icons.tsx`.
- That file is the single place to alias lucide names (`Add20Regular` style aliases were replaced by lucide). Swapping an icon library later means editing one file.
- Icon buttons must have `title` and/or `aria-label`.

## Accessibility

- Checkbox-like buttons: `aria-label` describing the action (“标记为完成”, “加入我的一天”).
- Modal shell (`Modal.tsx`) handles Escape and overlay click; do not reimplement.
- Inputs submit on Enter; Escape closes inline editors where implemented.
- Keep focus visible: global `:focus-visible` outline applies to interactive controls; remove `:focus-visible` outline on borderless inputs wrapped by a styled container (`.quick-add input`, `.step-input`, `.add-step-row input`, `.detail-title`, `.notes-area`, `.search-box input`) and on bordered inputs/selects that render their own single-layer Fluent focus ring or bottom accent bar (`.nav-rename-input`, `.group-name-input`, `.text-input`, `.form-row input`, `.settings-select`) to avoid double blue borders.

## Common Mistakes

- Declaring hooks after `if (!task) return null` — breaks hook order. Call hooks first.
- Using `React.ComponentProps` without importing `React` — import `type ComponentProps` from `react`.
- Importing `lucide-react` directly in a component instead of `./icons`.
- Storing derived values (counts, filtered lists) in state — compute with `useMemo` from `db`.
- Adding a second global add bar or moving authoring controls; the fixed bottom `QuickAdd` is the single entry point.
- Using Microsoft assets or the Microsoft To Do name/logo — prohibited; see quality guidelines.
